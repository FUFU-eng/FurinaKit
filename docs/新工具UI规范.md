# 新工具 UI 规范（FurinaKit）

> 一句话：**视觉语言必须和现有工具是一家；布局必须是为这个工具量身设计的，不是套模板。**
>
> 参照标杆（作者用 AI 做出来的、效果被认可的）：`signature-designer`（艺术签名）、`lan-transfer`（跨设备互传）。
> 这两个工具**风格和全站一致，但布局完全是它们自己的**——这才是标准。

---

## 第一部分：视觉语言（这部分是硬约束，必须一致）

### 0. 【硬规矩】公共外壳已经给过的东西，工具内部**一个都不许再画**

工具体验页的外壳（`ToolShell`，见 `tool-runner.tsx`）已经提供了：
1. **面包屑**：返回按钮 + `首页 / 分类 / 工具名`
2. **紧凑标题卡**：分类色条 + `<h1>工具名</h1>` + `<p>工具描述</p>`

所以工具内部**禁止**再出现：
- 任何形式的"图标 + 工具名 + 描述"标题框、横幅（hero banner）、大标题（`<h1>`、`text-xl font-bold` 等）；
- 与外壳描述重复的第二段说明文字。

违规代价很直接：**两个标题框叠在一起，白白吃掉一屏的垂直空间**，工作区被挤小。

**唯一允许保留的例外**：工具的核心操作控件可以放在顶部（比如模式切换标签页、品牌渐变色的**操作条**），但它必须
**只放控件、不放工具名与描述**。如果确实有一句非说不可的说明（例如"文件只在本机处理"），
就用一行小字或 `Badge`，不要再套一张卡片。

### 1. 文案：写"能做什么"，不写"界面上怎么展示"
- **要**：`查询域名的 A / AAAA / CNAME / MX / NS / TXT 记录，用于排查域名解析与邮件配置问题。`
- **不要**：`并发查询六类记录，结果按类型分卡片展示；查不到的类别会折叠起来，不再是一片「未查询到」。`（这是实现细节 + 自夸，属于典型的"AI 味"）
- 描述里**不许**出现：界面上怎么排版、怎么折叠、怎么高亮、比别的工具好在哪、感叹号堆砌、口语化的自我评价（"不再是一大片…"、"一眼就能看出…"这类）。
- 风格：客观、简洁、专业，像产品说明书。长度控制在**一句话**。

下面这些"材质感"必须和现有工具完全相同，否则就会突兀。

### 1. 卡片
```tsx
// 标准卡片
<div className="rounded-2xl border border-border/70 bg-card p-5 shadow-xs">
// 需要更"高级"的观感时（签名工具就是这么做的）：毛玻璃
<div className="bg-card/60 backdrop-blur-md border border-border/70 rounded-2xl p-5 shadow-sm">
```
- 圆角：大容器 `rounded-2xl`，里面的小控件 `rounded-xl` / `rounded-lg`。
- 边框：`border-border/70`（卡片）、`border-border/40` 或 `/50`（内部分隔）。
- 阴影：只用到 `shadow-xs` / `shadow-sm`，**不要用大阴影**。

### 2. 颜色（绝对禁止写死）
只能用主题变量：`bg-background` / `bg-card` / `bg-muted` / `text-foreground` / `text-muted-foreground` / `border-border` / `text-primary` / `bg-primary` / `text-destructive`。
- **禁止** `bg-white`、`text-black`、`bg-[#1e1e1e]`、`text-gray-500`。
- 你的软件有**浅色 / 深色 / 护眼**三套主题，写死颜色必然在其中一套下变成刺眼的色块。

### 3. 品牌色点缀（让工具显得"有设计感"的关键手法）
互传工具顶部那条**品牌渐变横幅**就是范例，值得学习：
```tsx
<div className="rounded-2xl border border-primary/20 bg-gradient-to-r from-primary/10 via-primary/5 to-transparent p-5">
```
用 `primary/10`、`primary/20` 这类**低透明度品牌色**做点缀，既醒目又不抢戏。

### 4. 组件与排版
- 只用 `@/components/ui/primitives`：`Button` / `Input` / `Textarea` / `Label` / `Select` / `Card` / `Badge` / `Alert` / `ProgressBar` / `PasteButton`。
- 图标用 `lucide-react`，`h-3.5 w-3.5`（工具栏小图标）或 `h-4 w-4`（按钮内图标）。
- 间距节奏：区块之间 `gap-5` / `gap-6` / `space-y-4` / `space-y-5`；卡片内边距 `p-5` / `p-6`。
- 正文 `text-sm`，说明文字 `text-xs text-muted-foreground`，代码/数据 `font-mono-accent text-xs`。

### 5. 错误提示（固定样式，不要自己发明）
```tsx
<div className="flex items-center gap-2 rounded-xl border-l-4 border-l-destructive bg-destructive/10 px-4 py-3 font-mono text-xs text-destructive">
  <AlertTriangle className="h-4 w-4 shrink-0" />{error}
</div>
```

## 第二部分：布局（必须为工具量身设计，禁止套模板）

### 先问自己一句：「用户拿这个工具**实际在做什么**？」
布局要跟着答案走。**不要不假思索地"左输入右输出"** —— 那只适合一种情况（见模式 A）。

### ⚠️ 但也不要走另一个极端：**"为不同而不同"同样是错的**
判断标准只有一条：**这个布局是不是最贴合它的任务**。
- 如果工具的本质就是「填两三个值 → 拿一段文字」，那么**通用表单（走元数据自动渲染）本身就是最优解**，不要为了"显得特别"硬做一套界面。
  例：Lorem 占位文本 —— 选类型、填数量、拿文字，通用表单就是最合适的。
- 反过来，只要**通用表单让用户看不到/做不到关键的事**，就必须自己做布局。
  例：
  - 生成器类（CSS 渐变）**必须能看到成品**，光给代码不行；
  - 结果本身是**结构化数据**（DNS 记录、证书信息、URL 字段、EXIF 参数）就该画成表格/字段卡，而不是糊成一段文字；
  - 工具的卖点是**前后对比**（SVG 优化省了多少）就必须把对比摆出来；
  - **边改边看**体验明显更好的（ASCII 艺术字）就别让用户点按钮。

### 布局模式目录（选最贴合的那个，也可以组合/创造新的）

| 模式 | 长什么样 | 适合什么工具 | 本项目范例 |
|---|---|---|---|
| **A. 转换对照** | 左输入 / 右输出，顶部一条操作栏 | 输入和输出**同等重要、需要互相对照**的转换 | JSON 格式化 |
| **B. 工作台（12 栏 4:8）** | 左侧参数配置，右侧大面积**实时预览** | 有大量参数、结果需要即时反馈的创作类 | **艺术签名** |
| **C. 两端对照（对称两列）** | 左右对称两块，各自代表一端 | 涉及**两个主体**的工具 | **跨设备互传**（电脑 ⇄ 手机） |
| **D. 表格数据** | 上传区 + **真正的表格预览**（带表头、斑马纹）+ 底部操作条 | 与表格/结构化数据打交道的 | （新增：CSV↔Excel） |
| **E. 队列批处理** | 文件列表（缩略图 + 状态 + 进度）+ 批量操作条 | 一次处理很多文件 | 图片压缩、图片转 PDF |
| **F. 文档预览** | 左编辑 / 右**渲染后的成品预览**（像一页纸） | 输出是"给人看的东西" | （新增：Markdown→PDF） |
| **G. 画布标尺** | 中间画布 + 可拖拽控制点 + 数值输入 | 需要精确空间操作 | 图片裁剪、混淆 |

### 设计时值得主动加的"贴合感"细节
- **方向/模式切换**：工具若支持双向或多模式，就在顶部给一个清晰的切换器（参考签名工具的 4 个模式标签页）。
- **实时检测与提示**：能自动识别输入格式的就自动识别，别让用户先选一遍（"检测到：JSON"这种提示很讨喜）。
- **结果预览要"像成品"**：输出是表格就画表格，是文档就画成一页纸，是图片就给足展示空间。
- **顶部横幅**：工具如果有一个核心卖点（比如"文件不出电脑"），可以用第一部分第 3 条的渐变横幅点出来。
- **空状态**：没内容时不要留白，给一句引导 + 一个「填入示例」。

## 第三部分：每个新工具都必须有的"体面"细节

- **填入示例**（空着进来会不知道干什么）
- **清空**（一键回初始态）
- **复制**（文本类结果必备）
- **人话错误提示**（"请输入完整的网址"，不是 `Error: invalid`）
- **操作有反馈**（结果变化或 `toast`，不能点了没反应）
- **记住用户输入**：用 `useToolDraft(工具id, 字段名, 初始值)`（`src/lib/use-tool-draft.ts`）。
  这是全项目统一机制，**每个新工具都要用** —— 用户切走再回来内容不能丢。

## 第四部分：自检清单（提交前逐条打勾）

**视觉语言**
- [ ] 没有写死颜色（搜 `#`、`bg-white`、`text-black`、`text-gray-`，一个都不许有）
- [ ] 只用 primitives 里的组件，没自己造按钮/输入框样式
- [ ] 卡片圆角/边框/阴影/内边距与现有工具的"材质感"一致
- [ ] 最外层没有 `min-h-screen`、没有整页背景（公共外壳已有）
- [ ] 在**浅色 / 深色 / 护眼**三套主题下都不突兀

**布局**
- [ ] 布局是**根据这个工具的任务模型**选的，能说清楚"为什么是这个布局"
- [ ] 不是无脑套"左输入右输出"；如果套了 A 模式，要能说明它确实最合适
- [ ] 空状态有引导，结果展示"像成品"（表格就是表格、文档就是文档）

**体面细节**
- [ ] 有「填入示例」「清空」「复制」（文本类）
- [ ] 错误提示用统一那套样式，文案是人话
- [ ] 用了 `useToolDraft`（切工具回来内容还在）
